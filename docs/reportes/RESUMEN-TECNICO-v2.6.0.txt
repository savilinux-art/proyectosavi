🎯 PROPÓSITO GENERAL

Sistema de gestión empresarial especializado en instalaciones tecnológicas
(domótica, audiovisuales, redes, seguridad). Ciclo completo:

  • Ventas (prospección → cierre)  ← sin titulo_venta ni monto_venta (v30)
  • Ventas de mostrador
  • Proyectos (derivados de ventas ganadas)
  • Cotizaciones
  • Instalaciones (planificación, ejecución, evidencias, checklist)
  • Inventario (productos, movimientos, apartados, salidas, devoluciones)
  • Clientes
  • Asignación de instaladores con notificaciones vía Telegram
  • Seguimiento GPS en tiempo real (Traccar + Reverb WebSocket)
  • Recordatorios automáticos (Telegram + Email + Web)
  • Certificados (SSL, CSD SAT, dominios)
  • Geocercas (alertas entrada/salida)
  • Roles y permisos granulares
  • Trazabilidad de materiales  ← ✅ COMPLETADA (19-oct)
  • App móvil offline-first     ← 🔄 PARCIAL (B-17 pull ✅ 21-oct; B-16 push pendiente)

El sistema NO usa el Auth facade de Laravel.
Login manual con Session::put('user_id'/'user_usuario'/'user_rol').

  ⚠️  user_id: SE ESCRIBE en AuthController.php:27, uso en lectura
      NO CONFIRMADO (grep amplio pendiente). El middleware usa
      user_usuario y user_rol.

Middleware custom (bootstrap/app.php):
  auth.session     → AuthSessionMiddleware      (verifica user_usuario)
  permiso:xxx      → PermisoMiddleware          (verifica permiso por SLUG)
  administrador    → AdministradorMiddleware    (rol === 'Administrador')

ALIAS QUE NO EXISTEN: auth, guest, verified.
⚠️ NUNCA usar middleware(['auth']) → rompe login para todos.
⚠️ La API SÍ usa 'auth:sanctum' (rutas en routes/api.php).
⚠️ Usuario NO tiene HasApiTokens todavía (B-02, Q-102) — BLOQUEANTE para móvil.
   Tests API usan actingAs($u, 'sanctum') que funciona sin HasApiTokens.

INCIDENTE 28-SEP-2026: alias auth.session no estaba registrado en
bootstrap/app.php → 19 rutas "protegidas" abiertas. Corregido en 73b924f.

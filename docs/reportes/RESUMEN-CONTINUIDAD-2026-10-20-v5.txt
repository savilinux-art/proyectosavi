### 3.1 B-11 — Bug de doble cast en show()
ANTES (roto):
    $instalacion = Instalacion::with(['proyecto'])->findOrFail($id);
    $instalacion->check_list = json_decode($instalacion->check_list);  ← TypeError

Modelo Instalacion tiene cast 'check_list' => 'array'. La asignación
sobre el atributo ya devuelve array; json_decode(array) explota en PHP 8.
El endpoint fallaba con 500 solo cuando check_list tenía datos.

DESPUÉS (correcto):
    $instalacion = Instalacion::with(['proyecto'])->findOrFail($id);
    return response()->json(['success' => true, 'data' => $instalacion]);

### 3.2 B-14 — Bug de doble codificación + 500 en vez de 404
ANTES (roto):
    try {
        $instalacion = Instalacion::findOrFail($id);      ← cae en catch → 500
        $instalacion->check_list = json_encode($request->check_list);  ← doble
        ...
        'data' => json_decode($instalacion->check_list)   ← TypeError
    } catch (\Exception $e) { return 500; }

DESPUÉS (correcto):
    $instalacion = Instalacion::findOrFail($id);          ← fuera del try → 404
    $instalacion->check_list = $request->check_list;      ← cast 'array'
    $instalacion->save();
    return response()->json(['success' => true, ..., 'data' => $instalacion->check_list]);

## 4. REGLAS NUEVAS / REFORZADAS (esta sesión)
--------------------------------------------------------------------------------

### Regla 12 (REFORZADA)
Archivos creados con `cat > ... << 'EOF'` pueden quedar en 0 bytes.
Verificar SIEMPRE con `wc -c` (no `wc -l`). `php -l` da falso positivo
en archivos vacíos. Los tests son el único chequeo que atrapa archivos
vacíos. REFUERZO: si el heredoc tiene código PHP con `\` o comillas
anidadas, prefiere nano a heredoc.

### Regla 13 (refuerzo)
"Class not found" en controller con namespace relativo → falta `use`
o falta `\` inicial.

### Regla 14 (refuerzo)
Pest --filter matchea nombre de it(), no de archivo.
Usar SIEMPRE path: php artisan test tests/Feature/XTest.php

### Regla 16 (refuerzo)
Antes de editar método existente: `awk '/public function NOMBRE/,/^    }$/'`.
sed -n 'X,Yp' falla con números aproximados.

### Regla 17 (NUEVA — confirmada 2 veces)
`awk -v var="$value"` interpreta secuencias de escape (\I → I).
Si $value tiene backslashes (namespaces PHP, regex, JSON), NO usar -v.
Usar heredoc single-quote o php -r con file_get_contents/file_put_contents.
Síntoma típico: "Class App\Http\Controllers\IlluminateHttpRequest not found".

### Regla 18 (NUEVA)
$this->withoutMiddleware() en tests deshabilita StartSession +
ShareErrorsFromSession. assertSessionHasErrors falla aunque validación
sí ocurrió. Solución: withoutExceptionHandling + try/catch ValidationException
+ verificar $e->errors().

### Regla 19 (NUEVA — confirmada 2 veces B-11 y B-14)
DOBLE CODIFICACIÓN SILENCIOSA. Si un modelo tiene cast 'array' o 'json':
  - NUNCA usar json_encode() al escribir ni json_decode() al leer.
  - El cast ya hace encode/decode.
Síntoma: el endpoint devuelve JSON "correcto" (doble encode + doble decode
en la response se cancela), pero `$model->refresh()->campo` devuelve un
string JSON en vez de array. Solo los tests de persistencia (con refresh())
lo detectan.

### Regla 20 (NUEVA)
COLISIÓN DE NOMBRES EN NAMESPACES DIFERENTES. InstalacionController existe
en App\Http\Controllers y App\Http\Controllers\Api. Antes de editar:
  grep -l "public function NOMBRE" app/Http/Controllers/*.php app/Http/Controllers/Api/*.php
Y verificar primera línea del archivo que abres.

### Regla 21 (NUEVA)
"FIX NO APLICADO" = archivo equivocado o nano sin guardar.
Si test falla con MISMO error después de "aplicar un fix", el fix no se
aplicó. Diagnóstico: awk '/public function M/,/^    }$/' archivo.
Si el código viejo sigue → archivo equivocado o guardado fallido.

### Regla 22 (NUEVA)
BACKUPS, NO REINVENCIÓN. Si fix falla 2 veces consecutivas:
restaurar backup y editar desde cero con nano, no acumular ediciones sobre
estado incierto.

### Regla 23 (NUEVA — VSCode)
VSCode resucita archivos renombrados desde terminal (git mv) si tiene
buffers abiertos con el path viejo. Síntoma: el archivo renombrado
reaparece como untracked con nombre viejo; el nuevo aparece D en git status.
Mitigación:
  1. Developer: Reload Window tras rename masivo.
  2. Verificar git status --porcelain dos veces (con sleep 5 entre medio).
  3. Hook pre-commit anti .php.php.

### Regla 24 (NUEVA)
lsof +D NO ve archivos abiertos por Electron/VSCode (buffers en RAM del
renderer, no fd). No concluir "no hay culpable" basándose solo en lsof.
Complementar con: ps aux | grep -iE "code|phpstorm|vim|nano"

### 6.1 Archivo NUEVO: app/Http/Requests/InstalacionEventoSimpleRequest.php

<?php

namespace App\Http\Requests;

class InstalacionEventoSimpleRequest extends InstalacionEventoRequest
{
    public function rules(): array
    {
        return [
            'tipo'             => ['required', 'in:incidencia,nota_agregada'],
            'capturado_at'     => ['required', 'date'],
            'descripcion'      => ['nullable', 'string', 'max:2000'],
            'payload_json'     => ['nullable', 'array'],
            'latitud'          => ['nullable', 'numeric', 'between:-90,90'],
            'longitud'         => ['nullable', 'numeric', 'between:-180,180'],
            'precision_metros' => ['nullable', 'integer', 'min:0'],
            'fuente'           => ['nullable', 'in:gps,network,cached,mock,no_disponible'],
            'foto'             => ['nullable', 'file', 'mimes:jpg,jpeg,png', 'max:10240'],
        ];
    }

    public function withValidator($validator): void
    {
        $validator->after(function ($v) {
            if (!$this->filled('descripcion') && empty($this->input('payload_json'))) {
                $v->errors()->add('descripcion',
                    'Se requiere descripcion o payload_json.');
            }
        });
    }
}

### 6.3 Método store() en app/Http/Controllers/Api/InstalacionEventoController.php

Añadir `use App\Http\Requests\InstalacionEventoSimpleRequest;` arriba.

    public function store(InstalacionEventoSimpleRequest $request, Instalacion $instalacion): JsonResponse
    {
        $this->autorizar($request, $instalacion);

        $payload = (array) ($request->input('payload_json') ?? []);
        if ($request->filled('descripcion')) {
            $payload['descripcion'] = $request->input('descripcion');
        }

        DB::transaction(function () use ($instalacion, $request, $payload) {
            $this->crearEvento($instalacion, $request->input('tipo'), $request, $payload);

            if ($request->hasFile('foto')) {
                $tipoFoto = $request->input('tipo') === 'incidencia' ? 'incidencia' : 'proceso';
                $this->guardarFotoSiViene($instalacion, $request, $tipoFoto);
            }
        });

        return response()->json([
            'message'     => 'Evento ' . $request->input('tipo') . ' registrado',
            'instalacion' => [
                'id'                  => $instalacion->id,
                'estatus_instalacion' => $instalacion->estatus_instalacion,
            ],
        ], 201);
    }

Reusa los métodos privados existentes:
  - autorizar($request, $instalacion)  → 403 si no asignado
  - crearEvento(...)                    → valida capturado_at en futuro → 422
  - guardarFotoSiViene(...)             → guarda en Storage + InstalacionFoto
